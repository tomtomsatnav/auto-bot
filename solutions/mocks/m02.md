# M02 solution: Notes service (runnable)

Roughly in the order you'd hit them:

## 1. `env` is a map, but the provider wants a list of strings (validate)
```
Inappropriate value for attribute "env": set of string required.
```
**Fix:** `env = ["NOTES_DIR=/data/notes"]`. The Docker provider uses the same `KEY=value` format as `docker run -e`. (It also fixes #3, see below.)

## 2. Wrong build context path (apply fails)
`${path.module}/app` means `infra/app`, which doesn't exist. The app is a sibling of `infra/`.
**Fix:** `context = "${path.module}/../app"`

## 3. `NOTE_DIR` vs `NOTES_DIR` (container crashes)
`docker ps -a` shows `notes-api` exited, and `docker logs notes-api` shows:
```
KeyError: 'NOTES_DIR'
```
The app reads `NOTES_DIR`, but Terraform set `NOTE_DIR`. **Fix:** spell the variable name correctly in the `env` list.

## 4. Volume permissions (container crashes)
```
PermissionError: [Errno 13] Permission denied: '/data/notes'
```
The volume is mounted at `/data`. That folder doesn't exist in the image, so a new volume is root-owned, and `appuser` can't create `notes/` in it. **Fix in the Dockerfile**, before `USER appuser`:
```dockerfile
RUN mkdir -p /data/notes && chown -R appuser:appuser /data
```
When a fresh, empty named volume is mounted over a directory that exists in the image, Docker copies that directory's contents **and ownership** into it.

**Gotcha:** if the volume was already created by an earlier failed attempt, it keeps its root ownership. Run `terraform destroy` (which removes the volume) or `docker volume rm notes-data`, then apply again. Explaining this out loud is a strong interview moment.

## 5. Port mismatch (unreachable)
`internal = 8080`, but uvicorn listens on **8000**. **Fix:** `internal = 8000` (external stays 8080).

## 6. `curl` health check in a slim image (unhealthy)
```dockerfile
HEALTHCHECK --interval=15s --timeout=3s --retries=3 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health', timeout=2)" || exit 1
```

## Fixed `infra/main.tf` (relevant parts)
```hcl
resource "docker_image" "notes" {
  name = "drills/notes-api:dev"

  build {
    context = "${path.module}/../app"
  }
}

resource "docker_container" "notes" {
  name  = "notes-api"
  image = docker_image.notes.image_id

  env = ["NOTES_DIR=/data/notes"]

  ports {
    internal = 8000
    external = var.external_port
  }

  volumes {
    volume_name    = docker_volume.notes.name
    container_path = "/data"
  }
}
```

**Note:** `terraform apply` can report success even while the container is crash-looping, because Terraform only checks that it *started*. Always confirm with `docker ps` and `docker logs`. Pointing that out shows you verify results rather than trusting exit codes.

# D06 solution: Multi-stage build

## Bug 1: wrong `COPY --from` path

The builder creates the venv at `/opt/venv`, not `/build/venv`:
```
COPY --from=builder /build/venv /opt/venv
ERROR: "/build/venv": not found
```
**Fix:** `COPY --from=builder /opt/venv /opt/venv`

## Bug 2: venv not on `PATH`

```
exec: "uvicorn": executable file not found in $PATH
```
The venv's executables are in `/opt/venv/bin`, which isn't on `PATH`. **Fix:** `ENV PATH="/opt/venv/bin:$PATH"`

## Bug 3: Python version mismatch between stages

The builder is **3.11**, the runtime is **3.12**. Packages were installed into `/opt/venv/lib/python3.11/site-packages`, but the runtime's Python looks in `python3.12`:
```
ModuleNotFoundError: No module named 'uvicorn'
```
This one is very confusing because the packages *were* installed. **Fix:** use the same Python version in both stages.

## Fixed

```dockerfile
# ---- build stage ----
FROM python:3.12 AS builder

WORKDIR /build
COPY requirements.txt .
RUN python -m venv /opt/venv \
    && /opt/venv/bin/pip install --no-cache-dir -r requirements.txt

# ---- runtime stage ----
FROM python:3.12-slim

ENV PATH="/opt/venv/bin:$PATH"

WORKDIR /app
COPY --from=builder /opt/venv /opt/venv
COPY main.py .

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Say this in the interview
- "Multi-stage builds keep compilers and build tools out of the production image. It's smaller and has less attack surface."
- "The two stages are separate filesystems. Only what you `COPY --from` crosses over, so paths and versions have to line up exactly."

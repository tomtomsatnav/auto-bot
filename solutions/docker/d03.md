# D03 solution: Won't start

## Bug 1: `CMD` is one string in exec form

```dockerfile
CMD ["uvicorn main:app --host 0.0.0.0 --port 8000"]
```
In exec form, the **first item is the executable**, so Docker looks for a program literally called `uvicorn main:app --host 0.0.0.0 --port 8000`:
```
exec: "uvicorn main:app --host 0.0.0.0 --port 8000": executable file not found in $PATH
```
**Fix:** one item per argument:
```dockerfile
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Bug 2: `ARG` doesn't exist at runtime

`ARG` values only exist **during the build**. When the container starts, `DATABASE_URL` isn't set, so `os.environ["DATABASE_URL"]` raises:
```
KeyError: 'DATABASE_URL'
```
**Fix:** use `ENV` for runtime defaults that aren't secret, and pass secrets at runtime:
```dockerfile
FROM python:3.12-slim

ENV APP_ENV=production

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py .

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```
```bash
docker run --rm -p 8000:8000 \
  -e DATABASE_URL=postgresql://billing:secret@db.internal:5432/billing d03
```

## Bug 3 (security): a credential baked into the image

`docker history d03 --no-trunc` shows build args, including the password. Anyone who can pull the image can read it. The same applies to `ENV`: never bake secrets into an image. In production, they come from a secret store (AWS Secrets Manager, GCP Secret Manager, Kubernetes Secrets) and are injected at runtime.

## Say this in the interview
- "`ARG` is build-time only, `ENV` persists into the running container, and secrets should be neither. They get injected at runtime."
- "Failing fast on missing config is good design. The crash is doing its job; the deployment just isn't supplying the value."

# D07 model answer: Dockerfile from scratch

```dockerfile
# Pin the tag for reproducible builds.
# In production you'd pin the digest too: python:3.12-slim@sha256:...
FROM python:3.12-slim

# Python behaviour suited to containers:
# no .pyc files, and logs appear immediately
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    APP_ENV=production

# Non-root user with a fixed UID
RUN useradd --create-home --uid 10001 appuser

WORKDIR /app

# Dependencies first, so this layer is cached unless requirements change
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Application code last, since it changes most often
COPY main.py .

USER appuser

EXPOSE 8000

# slim has no curl, so use Python for the health check
HEALTHCHECK --interval=15s --timeout=3s --start-period=5s --retries=3 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health', timeout=2)" || exit 1

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

`.dockerignore`:
```
.git
.gitignore
.venv
__pycache__
*.pyc
.env
.env.*
Dockerfile
.dockerignore
README.md
.terraform
*.tfstate*
```

## Walk through it like this
1. "Slim base pinned to a version, for a smaller image and reproducible builds."
2. "Requirements before code, for layer caching."
3. "`APP_ENV` as `ENV`, so it's a default that can be overridden with `-e`. Anything secret would be injected at runtime instead."
4. "Non-root user for least privilege."
5. "`0.0.0.0` so it's reachable from outside the container."
6. "Health check using Python, because slim images don't include curl."
7. "`.dockerignore` keeps secrets like `.env` and Terraform state out, and keeps the build context small."

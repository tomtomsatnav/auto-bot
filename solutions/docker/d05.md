# D05 solution: Unreachable and unhealthy

## Bug 1: uvicorn binds to `127.0.0.1`

No `--host` means uvicorn listens only on the container's loopback, so traffic arriving from outside the container is refused. **Fix:** `--host 0.0.0.0`.

## Bug 2: port mismatch

The platform standard is 8080. `EXPOSE 8080` and `-p 8080:8080` are both set, but the app listens on **8000**. `EXPOSE` is documentation only and doesn't change the app's port. **Fix:** `--port 8080`.

## Bug 3: `curl` isn't installed in slim images

`docker inspect d05 --format '{{json .State.Health}}'` shows:
```
/bin/sh: 1: curl: not found
```
The health check checks the wrong port too (8000). **Fix:** use Python, which is already in the image, and don't add a package just for a health check:
```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY main.py .

EXPOSE 8080

HEALTHCHECK --interval=10s --timeout=3s --retries=3 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8080/health', timeout=2)" || exit 1

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
```

## Say this in the interview
- "It works from inside the container but not from outside, so it's the bind address or the port mapping, not the app."
- "I'll check what the health check actually outputs rather than guessing. `docker inspect` shows the last few results."
- "Port numbers are a contract across the app, the Dockerfile, the run command and any load balancer, so I'll check every place that mentions one."

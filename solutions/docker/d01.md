# D01 solution: Build context

## Bug 1: `.dockerignore` excludes `requirements.txt`

**You'd see:**
```
COPY requirements.txt .
ERROR: failed to compute cache key: "/requirements.txt": not found
```
The file clearly exists in the folder, which is the clue. When a file exists but Docker says it's missing, check `.dockerignore`. The pattern `*.txt` (meant for log dumps) also matches `requirements.txt`.

**Fix:** Remove `*.txt`, or keep it and add an exception straight after it:
```
*.txt
!requirements.txt
```

## Bug 2: `COPY app/ .` flattens the folder

`COPY app/ .` copies the **contents** of `app/` into `/srv`, so you get `/srv/main.py`, not `/srv/app/main.py`. Uvicorn is told `app.main:app`, so it looks for `/srv/app/main.py`:
```
ERROR: Error loading ASGI app. Could not import module "app.main".
```

**Fix (either):**
```dockerfile
COPY app/ ./app/
```
or keep the copy and change the CMD to `main:app`. The first is better: it keeps the same layout as the repo, so local runs and container runs behave the same.

## Say this in the interview
- "The file exists locally but Docker can't see it, so something is filtering the build context. That's usually `.dockerignore`."
- "The build context is everything Docker sends to the builder. `.dockerignore` controls it, which keeps secrets and junk out and speeds up builds."

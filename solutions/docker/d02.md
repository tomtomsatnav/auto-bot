# D02 solution: System packages

## Bug: missing build dependencies for psycopg2

`psycopg2` (without `-binary`) compiles a C extension. The first real error in the pip output is:
```
Error: pg_config executable not found.
```
`pg_config` comes from `libpq-dev`, and compiling needs `gcc`. `slim` images leave both out.

**Fix option A (install build dependencies):**
```dockerfile
FROM python:3.12-slim

RUN apt-get update \
    && apt-get install -y --no-install-recommends gcc libpq-dev \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY main.py .

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Fix option B:** Change the requirement to `psycopg2-binary`, which ships precompiled. It's quick, but psycopg's own docs recommend building from source for production.

**Option C (best, and good to mention):** A multi-stage build compiles in a builder stage with `gcc` and `libpq-dev`, then copies the result into a slim runtime stage that only needs `libpq5`. That gives a smaller image with no compilers in production.

## Review point 1: `RUN apt-get update` in its own layer

That layer gets cached. Weeks later, a new `apt-get install` line reuses the stale package index and fails or installs old versions. **Always combine `update` and `install` in one `RUN`**, and clean `/var/lib/apt/lists` in the same step so the cache doesn't bloat the image.

## Review point 2: `COPY . .` before `pip install`

Every code change busts the cache and reinstalls every package. Copy `requirements.txt` first, install, then copy the code. (It also copies everything in the folder into the image, which is another reason for a `.dockerignore`.)

## Say this in the interview
- "The last line of pip output is usually generic, so I'll scroll up to the first real error."
- "Slim images trade size for missing tools. When a compile fails, it's usually a missing header or compiler."

# T02 solution: count and for_each

## Bug 1: `for_each` on a list
```
The given "for_each" argument value is unsuitable: the "for_each" argument must
be a map, or set of strings, and you have provided a value of type list of string.
```
**Fix:** `for_each = toset(var.services)`

(Why? `for_each` identifies each instance by a unique key. Lists allow duplicates and have an order; sets don't.)

## Bug 2: wrong key into a for_each resource
`random_password.db` is keyed by service name (`["auth"]`), not by number (`[0]`).
**Fix:** `random_password.db[var.services[count.index]].result`

## Bug 3: output on a counted resource
`local_file.env` is a list, so `.filename` on it fails. **Fix:** a splat expression:
```hcl
value = local_file.env[*].filename
```

## Part 2: why count is dangerous here

With `count`, instances are identified by **position**: `env[0]`, `env[1]`, `env[2]`. Remove `"auth"` (position 0), and `payments` moves from `[1]` to `[0]`, so Terraform thinks every file changed and rewrites or recreates them. With real resources, that means an outage.

**Refactor:**
```hcl
resource "local_file" "env" {
  for_each = toset(var.services)

  filename        = "${path.module}/output/${each.key}.env"
  content         = "DB_PASSWORD=${random_password.db[each.key].result}\n"
  file_permission = "0600"
}

output "service_files" {
  value = [for f in local_file.env : f.filename]
}
```
Now removing `"auth"` only destroys `auth`'s file and password.

**Rule of thumb:** use `count` for "N identical things" or on/off switches (`count = var.enabled ? 1 : 0`), and `for_each` for "one per named thing".

## Part 3: secrets
- `random_password.result` is marked sensitive, so the plan shows `(sensitive value)`. But it's still **stored in plain text in the state file**.
- `local_sensitive_file` would be better than `local_file`, because it hides the content in plan output.
- In real life: remote state with encryption and restricted access, and secrets kept in a secrets manager rather than in files.

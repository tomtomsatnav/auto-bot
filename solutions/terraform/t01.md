# T01 solution: Basics

| # | Where | Bug | Caught by |
|---|---|---|---|
| 1 | `variables.tf` | `replica_count` is a `number`, but its default is `"three"` | validate |
| 2 | `variables.tf` | `enable_debug` is a `bool`, but its default is `"yes"` | validate |
| 3 | `main.tf` locals | `var.enviroment` is misspelt | validate |
| 4 | `outputs.tf` | `local_file.app_conf` should be `app_config` | validate |
| 5 | `main.tf` readme | The reference is inside plain text, so it's written literally | **reading the output** |

## Fixes
```hcl
variable "replica_count" {
  type    = number
  default = 3
}

variable "enable_debug" {
  type    = bool
  default = true
}
```
```hcl
env = var.environment
```
```hcl
value = local_file.app_config.filename
```
```hcl
content = "Config generated at ${local_file.app_config.filename}"
```

## Worth knowing
- Terraform *does* convert some strings automatically: `"3"` becomes a number, and `"true"` becomes a bool. `"three"` and `"yes"` can't be converted, which is why they fail.
- Bug 5 is the important one. `validate` and `plan` both pass, and the file is created, but it says the wrong thing. **Always check the result, not just the exit code.**
- `${...}` inserts a reference into a string. Without it, text is just text.

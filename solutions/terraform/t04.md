# T04 solution: AWS S3

## Bug 1: `status = "enabled"` (validate)
```
expected versioning_configuration.0.status to be one of ["Enabled" "Suspended" "Disabled"], got enabled
```
**Fix:** `status = "Enabled"`. Allowed values are case-sensitive.

## Bug 2: `aws_s3_bucket.artifact` (validate)
**Fix:** `aws_s3_bucket.artifacts.id`

## Bug 3: invalid bucket name (only fails on a real apply)
The name comes out as `Platform_Drills-dev-artifacts`. S3 bucket names must be **lowercase** and **can't contain underscores**, so AWS would reject it at apply time. Plan doesn't check this.

**Fixes:** change the default to `platform-drills`, **and** stop it happening again with validation:
```hcl
variable "project" {
  type        = string
  description = "Project name, used in resource names"
  default     = "platform-drills"

  validation {
    condition     = can(regex("^[a-z0-9-]+$", var.project))
    error_message = "project must be lowercase letters, numbers and hyphens only (it's used in S3 bucket names)."
  }
}
```
Or normalise it: `lower(replace(var.project, "_", "-"))`.

## Bug 4 (security): `restrict_public_buckets = false`
The goal is a fully private bucket. All four settings should be `true`. With this one `false`, a public bucket policy could still grant public access.

## Say this in the interview
- "`validate` passing doesn't mean `apply` will work. The provider can't check everything AWS enforces, so I'll work out the real values."
- "Variable validation moves errors earlier, so they fail at plan with a clear message instead of halfway through an apply."
- "From a security point of view, all four public access block settings should be on for anything that isn't deliberately public."
